# システム構成・外部連携

## 1. 技術構成

```text
React / TypeScript / Vite
          ↓ HTTP / SSE
FastAPI / Pydantic
  ├─ フォルダ・画像走査
  ├─ 事前検証・命名計画
  ├─ パイプライン管理
  ├─ ジョブ・SQLite履歴管理
  ├─ ComfyUI API連携（拡大）
  ├─ ComfyUI API連携（AutoMosaic）
  ├─ Lanczos縮小
  └─ 設定管理
```

初期版はWindows上でローカル実行する。Reactをビルドし、FastAPIから静的ファイルとして配信する。

## 2. 工程実装

各工程は共通の入出力・結果形式を持つ独立コンポーネントとする。

```text
RenameStep
UpscaleStep
MosaicStep
```

パイプラインは有効工程を固定順に呼び、画像ごとの元ファイル、現在ファイル、一時ファイル、完成ファイルを追跡する。

## 3. ComfyUI連携

- 保存済みAPIワークフローをメモリ上で複製して使用する
- 元のワークフローJSONは変更しない
- 入力ノード、出力先、モザイク強度等の指定ノードだけを差し替える
- Image Finisher専用のComfyUI出力領域を使用する
- 1回に1画像を処理し、GPU工程の同時実行数は1とする
- 成果物を回収・検証してから専用出力領域を掃除する
- ComfyUI停止中はジョブを開始せず、利用者へ起動を案内する

## 4. LoRA Makerからの流用

次の汎用部分をImage Finisherリポジトリへ複製し、用途に合わせて改修する。

- FastAPIとReact/Viteのプロジェクト構成
- Pydantic設定検証と原子的保存
- SQLiteジョブキューと状態復元
- SSE接続と通知
- ComfyUI APIクライアント、ワークフロー差替え、成果物回収
- 危険パス検証と一時ファイル保護
- 開発・起動・ビルド用PowerShell
- バックエンドテストとフロントエンド検証

LoRA Maker固有のプロジェクト、データセット、動画、タグ付け、学習、models配置は複製しない。共有ライブラリ化は行わず、LoRA Makerへの実行時依存を持たせない。

## 5. ジョブ実行

バックエンドで同時実行数1のジョブキューを管理する。ジョブ内では画像を順番に処理する。ブラウザを再読込してもジョブは継続し、状態はSQLiteとSSEから復元する。

キャンセルは協調的に行い、現在画像の確定後に後続画像の開始を止める。外部プロセスやComfyUI処理を途中で強制終了しない。

## 6. 安全性

- 入力原本は読み取り専用として扱う
- 削除は専用一時領域と専用ComfyUI出力領域だけに限定する
- 空パス、ルート、入力、アプリルートを削除しない
- 既存完成ファイルを暗黙に上書きしない
- 完成ファイルを読み込み、寸法を検証してから成功とする
- 移動・検証完了前に中間成果物を削除しない

## 7. 将来拡張

PNG/JPEG/WebP変換、メタデータ除去、色空間統一、投稿先別プリセット、ZIP化等は追加工程として実装可能な構造にするが、初期版の対象外とする。
